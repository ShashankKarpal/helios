2026-10-23, relay refusals (code only, no store change):

- Relay: a batch heliosd refuses with HTTP 422 is set aside instead of failing every cycle. The reason (the status and the daemon's text, never record contents; FastAPI's echoed input is dropped) goes into `~/Helios/relay/refused/refusals.jsonl` first, then the local copy moves to `refused/`, and the spool host's copy moves from its inbox to `refused/` beside it. Neither side ever overwrites a different batch (a different copy under one name is kept beside it under a hash-suffixed name), and nothing in either `refused/` folder is pruned or deleted before heliosd acks that batch with the same bytes; the host's copy is checked by its sha256 before it is removed. The other batches of the cycle carry on and a refusal alone no longer stops `LAST_OK`. A refused batch is retried once automatically after every heliosd restart (`/api/health` now reports `started_at`), so a fix or an upgrade, or a relay cycle caught between a code reset and the restart, needs no hand work. `m4_spool_pull.py refused` lists them and `requeue <name or path>|--all` copies them back for the next cycle. Every other failure (401, 5xx, a lost connection, a 2xx without ack) still waits in staging as before.
- Relay hardening from the review: an error on one batch (a disk error, an ssh that hangs) is counted and never stops the rest of the cycle; every remote step is a quoted shell line that prints one word and is tested by running it under zsh; a file name the receiver could not have written is never posted or passed to the spool host; `[relay] remote_spool` is checked at start; batches already staged are replayed even when the fetch from the spool host fails; one run at a time.
- Watchdog: one error row, `relay_refused`, while `refused/` holds a batch (count, newest refusal, the newest reason of a batch still held, the review and requeue steps), in `/api/freshness` and the MCP `freshness` tool. The hourly macOS notification now keys its 6-hour cooldown by device as well as metric and status, so one row in its cooldown never hides another (a Whoop error and refused relay batches were both "* error"), and the relay row reads "2 relay batches refused by heliosd, kept for review".

2026-10-21, single-source Phase 3 (the live Bridge; Bridge 1.1 (2); code only, no schema change, nothing in the store rewritten):

- Bridge outbox (C10, C3): one durable file per page, every write checked; a page leaves the phone only on an ack, a refusal (kept, parked on the phone) or once its stream's anchor moved past it. Nothing is dropped for its attempt count any more (1.0 dropped a page after eight tries, which lost dated and 48-hour sweep pages); the dated sweeps are never queued and read the same days again until a run is fully acked. The 1.0 outbox moves over page by page at the first launch. Tested on the Mac (`ios-bridge/BridgeCore`, `swift test`): a crash at every durable step, a real SIGKILL at every durable step, random histories with lost acks and refusals.
- Bridge sync (C1, C2, C4, C5, C6, C7, C8): one drain per type (a wake joins the running one), a failed page waits with backoff instead of parking the type, "waiting for unlock" clears on the next success, per-type progress, Reset and re-pull for every type without the 3-year dated sweep, a Host change resets the link status and stops running sends, a re-read of one type over chosen days.
- Bridge classes (plan v2 Phase 3): every sample with its true type, metadata, device, source revision, sync fields and millisecond instants; workouts with statistics, events, activities, totals and routes; routes with the workout HealthKit associates them with; ECG voltages; activity summaries; about 95 more types; Apple's own daily totals for steps, active and basal energy as a check value (C9). Read permission for them is asked once ("Allow the new Health types").
- Bridge cadence: observer wakes flush the outbox first and always complete inside a 20-second budget; a background processing task beside the refresh task; a send at unlock; a wake log on the status screen.
- heliosd: batch schema 2. Its samples feed the unchanged samples path with their v1 fields (the samples rows equal those of the same batch sent as v1); everything else lands in `raw_records` (and route points in `route_points`) with the record's own identity, idempotent, tombstone-aware, in the same transaction. A schema or key the daemon does not know is refused (HTTP 422, ack false), never acknowledged with parts dropped. No canonical workout, ring or ECG row is built from Bridge records yet (Phase 4).
- Review fixes before the deploy (one independent read-only review, 11 findings, all ruled before anything went live):
  - Bridge: an empty page never moves a type's anchor, so a type turned off and on again sends what was written while it was off.
  - Bridge: a record whose parts cannot be read (a workout's routes, a route's points, an ECG's voltages) no longer stops its type: it is left out of its page and held in a "read again" list, on disk and before the anchor moves past it, and later runs fetch it by uuid. It leaves the list only once the Mac acked it or its deletion arrived. A page the Mac finds too large is halved down to one record; one record over the relay's 32 MB limit cannot be split (a 10-hour route is about 3 MB).
  - Bridge: the 20-second wake budget bounds everything. HealthKit gets its completion at the deadline whatever the work is doing, an upload under a deadline is one attempt that ends by it, no Health read starts after it, and drains with a deadline run at most three at once.
  - Bridge: a file that exists but cannot be read (before the first unlock after a restart) is never taken for a missing one: an unreadable resume point stops the drain instead of starting the type over, the cursors are never overwritten with an empty copy, an outbox page is left in place and read again, and the temporary-folder fallback never moves the 1.0 outbox.
  - Bridge: blood glucose is swept 14 days back (the type with anchored misses on record); other types keep 48 hours, and an older gap is a date-range re-read.
  - heliosd: a field inside a record that the daemon has no column for is kept in `children` (`extra_fields`, also odd route points), never dropped; a record that is not an object is refused (HTTP 422); a record without its identity is counted in the ack (`skipped_no_id`); a registered sample whose time cannot be read is counted (`bad_record`) and the rest of the batch is stored, its raw row included.
  - Tests: crash points now include parking, unparking and every cursor save; the crash workload holds a record to read again and parks a refused page; the replay model turns a type off and on and holds records whose parts fail for a while; every new test was first seen to fail against the old behaviour.
- Verification fixes (a second independent review of the fixes: no Critical or High; the owner's rulings of 2026-10-22):
  - Bridge: the read-again run sends pages no larger than the type's own, halves them on a 413, moves a refused page to the end of the list and waits an hour for that type (Sync Now tries at once). Records whose parts never read stay held and counted as "Read again later".
  - Bridge: HealthKit's completion also fires when iOS ends the background time before the 20-second timer, and the wake's deadline is the earlier of 20 seconds and the time iOS has left. A deadline cut is "out of time": no link failure, no outage alert, no backoff, and a processing task is scheduled.
  - Bridge: a cursors file that does not decode starts workouts, routes and ECGs again from the beginning before the engine starts (their read-again list was in it); the damaged copy is marked only afterwards, so a crash on the way means the next launch does it again.
  - Bridge: an outbox folder that cannot be listed counts as unreadable, never as empty; a NaN or infinity from another app is sent as text instead of stopping its type; a sync started after an interrupt or a Host change no longer stops with the drain that interrupt cancelled; the storage-fallback note says what happens.
  - Bridge tests: the once-only completion, the deadline timer, the wake deadline, the upload time limit and the upload plan moved into BridgeCore with tests.
  - heliosd: a uuid, type, source name or day that is not text is refused (HTTP 422) before any write, instead of failing the batch for good; the original of a value stored as null (an out-of-range sync version, a NaN in a route point or a daily total) is kept in `children`.

2026-10-18, Wave 4 (code only; no stored data rewritten):

- Morning brief: the local model's narrative was rejected on every try on any day still in progress, and the template was served silently. The prompt always asked for steps and for every rule action in full, while the validator rejects any mention of a metric held back from the narrative (a running total of the day, a stand-in device, a value not in yet). The prompt now lists only what may be said, names the words to avoid in plain terms, and gives the model only the rule actions that do not name a held-back metric (the others keep the engine's text, in rule order); a retry carries a plain instruction; a model failure or three rejected tries are logged without numbers. The red-recovery action reads "Keep today's load low" (same rule key, same action id). The validator is unchanged.
- Labs: the reader reads result rows (printed test name, result, H or L flag, unit, reference interval, method) instead of the first number after one of 20 keywords. Every row is listed under the report's own name; a known name is filed under its canonical name by whole-name match; the collection date is preferred and a birth date or a future date is never the panel date; thousands separators and the first printed interval are handled; urine rows carry a "Urine" prefix; ratios and estimates are marked and start unticked, as do rows read with low confidence; the confirm screen shows the printed name when it differs.
- Labs, one unit per test (`heliosd/insights/lab_units.py`): every known test has a home unit (the unit of the owner's first imported panel) and a table of the other common unit systems with the standard conversion into it (US conventional, SI and lab-specific spellings and scales, for example mmol/L, umol/L, g/L, 10^9/L, lakhs/cumm, HbA1c in mmol/mol). The value and its reference interval are converted before the owner confirms, and the screen shows what the report printed. A unit the table does not know is never guessed: the row keeps its printed unit, is marked, and starts unticked.
- Backup: `server/tools/helios_backup.py run-if-due` does the run only when today has no backup yet; the launchd template fires it at 02:30, 09:30, 14:30 and 20:30, so a night the Mac was off or offline is made up the same day. An export-only run never touches LAST_OK when a remote is configured.

2026-10-08, fix program Wave 1 (code only; audit reports of the same day), the daemon, actions and security items:

- Actions keep their status (A2, audit T3). Action ids are `<date>:<category>:<rule key>` instead of a position; the persist step never rewrites or deletes a row the owner adopted, dismissed or marked done; the model may reword a still-suggested action only when the day's rule categories are all distinct, and can never reorder, add or drop one; a positional row written before this change is re-filed under the stable id when its text is exactly a current rule's text, and otherwise stays resolved under its old id until it leaves the 7-day list. Before, DuckDB kept the status of a resolved row and replaced its text with whatever rule sat at that position after the next regeneration. Rollback note: a revert brings the positional writer back, which inserts positional suggestions beside surviving stable resolved rows (an action can then show twice) until a re-upgrade migrates them by text again.
- Whoop lands within minutes of being scored (A3, audit K3 and T13). The first background tick runs `[server] first_tick_seconds` after startup (default 120 s) instead of a fixed hour, and a wake-window poller pulls Whoop every `[whoop] wake_poll_minutes` (default 15) inside `wake_window` (reporting-zone hours, default 05:00 to 10:00) until the night that ends today has landed: a scored main sleep with stages and the scored recovery linked to it by `sleep_id` with a score. Then it waits for the next day; revisions come with the hourly 8-day pull. All pulls run one at a time (two concurrent token refreshes would invalidate each other), every attempt is recorded for the freshness report, and a failed hourly pull no longer skips the rest of the tick. `POST /api/whoop/pull` clamps `days` to 1 to 400, runs a real pull at most once a minute (otherwise it answers `skipped: rate_limited` with the last attempt's outcome), and answers 502 when the pull fails, so the web's Pull latest can call it first.
- Logs with timestamps at INFO (A13, audit P12). Nothing configured the daemon's logger, so only warnings reached the server log, without a time, and the INFO summaries (each recompute tick, each Whoop pull, the shutdown record) were lost. `run()` now installs one timestamped handler with the daemon's logger at INFO (third-party INFO chatter stays out) and passes uvicorn its own log config with a timestamp in front of both formatters; the access log also drops query strings, which carried the Whoop OAuth callback's code. Configuration happens only in `run()`, so tests and the test client are unaffected.
- Client allowlist and TLS fail-closed (A24, owner decision of 2026-10-08). `[server] allow_clients = "tailnet"` (the default) serves loopback, the Mac's own interface addresses (read from `ifconfig`, cached a minute, refreshed on a miss at most every 5 s; an IPv6 link-local address must match with its zone) and a peer from the Tailscale ranges 100.64.0.0/10 and fd7a:115c:a1e0::/48 when the connection arrived on the Mac's own Tailscale (`utun`) address, read in the same `ifconfig` pass (the Wave 1 review: some hotel, carrier and office networks are numbered from 100.64.0.0/10, and a source in it can be spoofed while tailscaled is down), and answers 403 on every path to any other client, the PWA shell included; refusals are logged by address, once per address per 10 minutes. `"any"` is the rollback. The bind is unchanged, so startup does not depend on tailscaled, and uvicorn no longer honours X-Forwarded-For (`proxy_headers` off), so the peer the allowlist judges is always the socket's. A configured `tls_cert` or `tls_key` that is missing, unreadable, not PEM or not a matching pair, or only one of the two, stops the start with exit 2 and the path in the message; before, the daemon served plain HTTP on the same port.

- Overnight relay tooling (2026-09-06): `server/tools/m1_spool_receiver.py`, a standard-library spool receiver for an always-on second Mac that speaks the Bridge's `/ingest` contract (token, `{"ack": true}` only after fsync, 401/413/507 refusals that leave the Bridge outbox intact, `/api/health` with queue depth and free disk), and `server/tools/m4_spool_pull.py`, which rsyncs the inbox, replays into the local `/ingest`, and deletes remote copies only after heliosd acks; replay is idempotent by sample uuid. LaunchAgent templates for both machines; see SETUP.md. Measured motive: the longest overnight gap in Bridge batches was 7 to 11 hours on 9 of the last 14 nights.
- Durability: `POST /api/admin/export` writes the irreplaceable tables (events, labs, narratives, whoop_cache, actions, chat_messages, profile_facts) as checksummed gzipped JSONL under `~/Helios/backup/<date>/`; `server/tools/helios_backup.py run` drives it nightly, prunes, optionally rsyncs to a second machine and verifies remote checksums, and touches `LAST_OK` only when everything passed; `restore-test` loads an export into a fresh schema and compares counts. The 2026-08-17 "weekly full plus nightly incremental" shape was vetoed with evidence: the tables total a few hundred rows, so a nightly full is a few kilobytes.

Security fixes from the 2026-09-02 fleet audit. Live verification against the running daemon: the traversal URL that returned the config file before the restart returns the SPA shell after it; the multi-statement and `read_text` queries return 400; a plain SELECT still works.
