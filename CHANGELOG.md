2026-10-23, relay refusals (code only, no store change):

- Relay: a batch heliosd refuses with HTTP 422 is set aside instead of failing every cycle. The reason (the status and the daemon's text, never record contents; FastAPI's echoed input is dropped) goes into `~/Helios/relay/refused/refusals.jsonl` first, then the local copy moves to `refused/`, and the spool host's copy moves from its inbox to `refused/` beside it. Neither side ever overwrites a different batch (a different copy under one name is kept beside it under a hash-suffixed name), and nothing in either `refused/` folder is pruned or deleted before heliosd acks that batch with the same bytes; the host's copy is checked by its sha256 before it is removed. The other batches of the cycle carry on and a refusal alone no longer stops `LAST_OK`. A refused batch is retried once automatically after every heliosd restart (`/api/health` now reports `started_at`), so a fix or an upgrade, or a relay cycle caught between a code reset and the restart, needs no hand work. `m4_spool_pull.py refused` lists them and `requeue <name or path>|--all` copies them back for the next cycle. Every other failure (401, 5xx, a lost connection, a 2xx without ack) still waits in staging as before.
- Relay hardening from the review: an error on one batch (a disk error, an ssh that hangs), or in the restart retry, is counted and never stops the rest of the cycle; every remote step is a quoted shell line that prints one word only when it did its job (a copy it cannot hash, or two names both taken by other bytes, print nothing) and is tested by running it under zsh; a file name the receiver could not have written is never posted or passed to the spool host and is named in the log; `[relay] remote_spool` is checked at start; batches already staged are replayed even when the fetch from the spool host fails, with the remote steps skipped for that cycle; one run at a time.
- Watchdog: one error row, `relay_refused`, while `refused/` holds a batch (count, newest refusal, the newest reason of a batch still held, the review and requeue steps), in `/api/freshness` and the MCP `freshness` tool. The hourly macOS notification now posts at most once per tick, for the worst row whose 6-hour cooldown has run out, naming how many more are due ("..., and 3 more"), and starts the cooldown of every due row together; the cooldown is keyed by device as well as metric and status. So a lasting set of problems posts at most once every 6 hours, and a new problem posts at the next tick even while an older one is in its cooldown (a Whoop error and refused relay batches were both "* error"). The relay row reads "2 relay batches refused by heliosd, kept for review".

2026-10-21, single-source Phase 3 (the live Bridge; Bridge 1.1 (2); code only, no schema change, nothing in the store rewritten):

- Bridge outbox (C10, C3): one durable file per page, every write checked; a page leaves the phone only on an ack, a refusal (kept, parked on the phone) or once its stream's anchor moved past it. Nothing is dropped for its attempt count any more (1.0 dropped a page after eight tries, which lost dated and 48-hour sweep pages); the dated sweeps are never queued and read the same days again until a run is fully acked. The 1.0 outbox moves over page by page at the first launch. Tested on the Mac (`ios-bridge/BridgeCore`, `swift test`): a crash at every durable step, a real SIGKILL at every durable step, random histories with lost acks and refusals.
- Bridge sync (C1, C2, C4, C5, C6, C7, C8): one drain per type (a wake joins the running one), a failed page waits with backoff instead of parking the type, "waiting for unlock" clears on the next success, per-type progress, Reset and re-pull for every type without the 3-year dated sweep, a Host change resets the link status and stops running sends, a re-read of one type over chosen days.
- Bridge classes (plan v2 Phase 3): every sample with its true type, metadata, device, source revision, sync fields and millisecond instants; workouts with statistics, events, activities, totals and routes; routes with the workout HealthKit associates them with; ECG voltages; activity summaries; about 95 more types; Apple's own daily totals for steps, active and basal energy as a check value (C9). Read permission for them is asked once ("Allow the new Health types").
- Bridge cadence: observer wakes flush the outbox first and always complete inside a 20-second budget; a background processing task beside the refresh task; a send at unlock; a wake log on the status screen.
- heliosd: batch schema 2. Its samples feed the unchanged samples path with their v1 fields (the samples rows equal those of the same batch sent as v1); everything else lands in `raw_records` (and route points in `route_points`) with the record's own identity, idempotent, tombstone-aware, in the same transaction. A schema or key the daemon does not know is refused (HTTP 422, ack false), never acknowledged with parts dropped. No canonical workout, ring or ECG row is built from Bridge records yet (Phase 4).
- Review fixes before the deploy (one independent read-only review, 11 findings, all ruled before anything went live):
  - Bridge: an empty page never moves a type's anchor, so a type turned off and on again sends what was written while it was off.
  - Bridge: a record whose parts cannot be read (a workout's routes, a route's points, an ECG's voltages) no longer stops its type: it is left out of its page and held in a "read again" list, on disk and before the anchor moves past it, and later runs fetch it by uuid. It leaves the list only once the Mac acked it or its deletion arrived. A page the Mac finds too large is halved down to one record; one record over the relay's 32 MB limit cannot be split (a 10-hour route is about 3 MB).
  - Bridge: the 20-second wake budget bounds everything. HealthKit gets its completion at the deadline whatever the work is doing, an upload under a deadline is one attempt that ends by it, no Health read starts after it, and drains with a deadline run at most three at once.
  - Bridge: a file that exists but cannot be read (before the first unlock after a restart) is never taken for a missing one: an unreadable resume point stops the drain instead of starting the type over, the cursors are never overwritten with an empty copy, an outbox page is left in place and read again, and the temporary-folder fallback never moves the 1.0 outbox.
  - Bridge: blood glucose is swept 14 days back (the type with anchored misses on record); other types keep 48 hours, and an older gap is a date-range re-read.
  - heliosd: a field inside a record that the daemon has no column for is kept in `children` (`extra_fields`, also odd route points), never dropped; a record that is not an object is refused (HTTP 422); a record without its identity is counted in the ack (`skipped_no_id`); a registered sample whose time cannot be read is counted (`bad_record`) and the rest of the batch is stored, its raw row included.
  - Tests: crash points now include parking, unparking and every cursor save; the crash workload holds a record to read again and parks a refused page; the replay model turns a type off and on and holds records whose parts fail for a while; every new test was first seen to fail against the old behaviour.
- Verification fixes (a second independent review of the fixes: no Critical or High; the owner's rulings of 2026-10-22):
  - Bridge: the read-again run sends pages no larger than the type's own, halves them on a 413, moves a refused page to the end of the list and waits an hour for that type (Sync Now tries at once). Records whose parts never read stay held and counted as "Read again later".
  - Bridge: HealthKit's completion also fires when iOS ends the background time before the 20-second timer, and the wake's deadline is the earlier of 20 seconds and the time iOS has left. A deadline cut is "out of time": no link failure, no outage alert, no backoff, and a processing task is scheduled.
  - Bridge: a cursors file that does not decode starts workouts, routes and ECGs again from the beginning before the engine starts (their read-again list was in it); the damaged copy is marked only afterwards, so a crash on the way means the next launch does it again.
  - Bridge: an outbox folder that cannot be listed counts as unreadable, never as empty; a NaN or infinity from another app is sent as text instead of stopping its type; a sync started after an interrupt or a Host change no longer stops with the drain that interrupt cancelled; the storage-fallback note says what happens.
  - Bridge tests: the once-only completion, the deadline timer, the wake deadline, the upload time limit and the upload plan moved into BridgeCore with tests.
  - heliosd: a uuid, type, source name or day that is not text is refused (HTTP 422) before any write, instead of failing the batch for good; the original of a value stored as null (an out-of-range sync version, a NaN in a route point or a daily total) is kept in `children`.
